Analysis Summary

Current Architecture

TextGVar_MJM.mqh — Low-level primitives:

  • TextGVar_BuildName() / TextGVar_GetGenericName() — name construction
  • TextGVar_Create() — creates text objects
  • TextGVar_Read() — reads values
  • TextGVar_Delete() / TextGVar_DeleteAll() / TextGVar_DeleteAllExcept() — deletion

IndicatorMetadata_MJM.mqh — Mid-level abstractions:

  • SanitizeShortName(), ExtractIndicatorName(), AcquireInstanceID()
  • CreatePatternAndPrefix() — wraps TextGVar_Create
  • SetPlotCount(), CreatePlotMetadata(), CreateParameterMetadata() — wrap TextGVar_Create
  • HandleIndicatorDeinit() — wraps TextGVar_DeleteAll and TextGVar_Create

Ind_ATR_MJM.mq5 — Source indicator:

  • Defines TEXTGVAR_PREFIX and TEXTGVAR_REINIT locally
  • Maintains 5 global variables: g_IndyName, g_TextGVar_Pattern, g_TextGVar_DeletePrefix, g_MyWindow, g_InstanceID
  • OnInit performs 6 sequential IndicatorMetadata function calls
  • OnDeinit calls HandleIndicatorDeinit()

What Needs Standardization

The indicator currently uses IndicatorMetadata functions (good), but each of the 14 SIs would need to:

  1. Duplicate the same #define statements
  2. Declare the same 5 global variables
  3. Call the same 6-function initialization sequence in the same order
  4. Pass the same 5 parameters to HandleIndicatorDeinit()

#define INSTANCE_COUNTER_NAME "MJM_InstanceCounter"

int AcquireInstanceID()
{
   double counterValue = 0;
   
   if(GlobalVariableCheck(INSTANCE_COUNTER_NAME))
      counterValue = GlobalVariableGet(INSTANCE_COUNTER_NAME);
   
   if(counterValue >= 1000000)
      counterValue = 0;
   
   int instanceID = (int)counterValue;
   GlobalVariableSet(INSTANCE_COUNTER_NAME, counterValue + 1);
   
   Print(...);
   return instanceID;
}

The source indicator already doesn't touch the terminal global variable directly—it just calls AcquireInstanceID() (line 52).

In the proposed plan, InitIndicatorContext() would call AcquireInstanceID() internally and store the result in g_Ctx.InstanceID. So the abstraction stays the same; it just moves one level deeper (indicator calls InitIndicatorContext(), which calls AcquireInstanceID(), which interacts with the terminal global variable).

No changes needed to the ID generation mechanism itself. It's already properly isolated.
