when you change a line color or line width in an MT5 indicator, is the running code aware?
Claude2026-01-18 13:42 UTC

Sunday, January 18, 2026, 12:00 PM CST

No. When you change a line color or width via the indicator properties dialog (right-click → Properties), the running indicator code is not notified and receives no callback or event.

What happens:

  1. The terminal handles the visual change directly at the rendering layer
  2. OnCalculate() is not triggered
  3. No OnChartEvent() is fired
  4. The input variable values in your code remain unchanged (they reflect compile-time/initialization values, not runtime UI changes)

The disconnect:

  • Colors/widths set via SetIndexBuffer() + PlotIndexSetInteger() at init are defaults
  • User changes via Properties dialog override these visually but don't write back to your code's variables
  • If your indicator calls PlotIndexSetInteger(index, PLOT_LINE_COLOR, ...) again (e.g., in OnCalculate()), it will overwrite the user's manual change

Implication:

If your indicator dynamically sets colors (e.g., based on conditions), it will continuously override any manual user adjustments unless you build in logic to detect and respect user preferences — which MT5 doesn't natively support.

Can the code get the current line properties from somewhere?
Claude2026-01-18 13:43 UTC

No. MQL5 provides no function to read current plot properties.

PlotIndexSetInteger() and PlotIndexSetDouble() are write-only. There is no PlotIndexGetInteger() or equivalent getter.

What you cannot retrieve:

  • Current line color (including user-modified)
  • Current line width
  • Current line style
  • Any plot property after initialization

Workarounds (limited):

  1. Track your own state — Store what you set in global variables, but this only reflects what your code set, not user overrides

  2. Object-based drawing instead of plot buffers — If you draw with OBJ_TREND, OBJ_HLINE, etc., you can read properties back via ObjectGetInteger(chart_id, name, OBJPROP_COLOR) and similar. But this abandons the buffer/plot system entirely.

Bottom line:

The plot buffer system is opaque. You write properties, the terminal renders, but there's no bidirectional communication. If you need runtime awareness of visual state, objects are the only path.

It didn't detect the change. Changing input parameters via the Properties panel triggers a full reinit cycle:

  1. OnDeinit() called (your TextGVar_DeleteAll() runs)
  2. OnInit() called with new InpTEMAColor / InpTEMAWidth values
  3. TextGVar_Create() writes the new values

You're modifying inputs, not plot properties directly. Input changes cause indicator reinitialization.
