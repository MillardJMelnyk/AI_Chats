Per-tick indicator + signal processing (lines 3102–3115): After each tick, if replay_n >= warmup_threshold, it calls:

This recomputes indicators on the growing replay_* arrays. Then:

The inner signal loop (line 3116): for(int i = process_start; i < replay_n; i++) — because process_start is replay_n - 1 in the steady state, this loop body executes exactly once per call, processing only the current last bar i = replay_n - 1.

Why signals = 0:

The cocking gate (line 3263):

i = replay_n - 1 always. So i < replay_n - 1 is always false. Chart_TryCock never executes. The cock is never set. No signal candidate ever forms.

The same guard (i < replay_n - 1) also prevents Chart_ResetCycle from running at line 3266, and qualified_cross reset at line 3466. State never advances past bar 0.

The design of the inner loop assumes it's processing a bar that is "finished" (not the current open bar). But the loop only ever sees the last open bar. All the cross-bar logic that requires looking at a bar already closed before the next bar opens is permanently blocked.

Why it's slow:

Chart_ComputeIndicators is called with from_bar = replay_n - 1. Inside it, prev_for_calcs = from_bar + 1 = replay_n. CalcTEMA receives replay_n as its start parameter — which is past the end of the array, so it likely falls back to a full recompute from bar 0 on every call. This happens ~180 times (once per new bar created), and each call recomputes TEMA/EMA/KC over the full growing array.

Summary of the structural mismatch:

The code was written assuming bar-at-a-time processing where when bar i is processed, bar i is already closed and bar i+1 is the live bar. But the tick loop processes each bar exactly once — as the last (replay_n - 1) bar — which means every bar is processed as if it is live/open, which disables all the logic guarded by i < replay_n - 1. The fix requires either processing bars with a one-bar lag (process up to replay_n - 2 per tick, flush replay_n - 1 when it closes) or restructuring to do a single post-hoc pass over all completed bars after the tick loop.
