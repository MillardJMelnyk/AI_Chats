Audit: Ind_Travel_MJM.mq5

Bug 1 — No-tick bars write 0.0 instead of EMPTY_VALUE [Functional]

In CalculateHistoricalTravel, when copied <= 1, the function returns early and the caller assigns historicalTravel = 0.0 to the buffer. This overwrites the SetIndexBuffer default (EMPTY_VALUE = DBL_MAX) with 0.0, making unavailable-tick bars visually indistinguishable from genuinely flat bars.

Fix: CalculateHistoricalTravel should return bool. Caller writes EMPTY_VALUE on false.

Bug 2 — Live bar uses close[]; historical uses tick.bid [Methodological inconsistency]

Historical mode fetches raw ticks via CopyTicksRange and processes tick.bid. Live mode derives movement from successive close[currentBar] values. On most MT5 brokers, close[currentBar] == last bid, so they're numerically equivalent — but this is broker-dependent, not guaranteed. If a broker's close reflects mid or ask, live travel will diverge from historical travel for the same bar.

Fix: Live bar should call SymbolInfoTick(_Symbol, tick) and pass through GetTravelTickPrice().

Bug 3 — COPY_TICKS_INFO excludes last-only ticks [Silent data loss, instrument-dependent]

COPY_TICKS_INFO returns ticks where bid or ask changed. If tick.bid == 0 for a tick (some instruments, some brokers), and only tick.last carries price data, that tick is filtered out at the CopyTicksRange call — GetTravelTickPrice's fallback to tick.last never fires. The tick is silently dropped.

Fix: Use COPY_TICKS_ALL and let GetTravelTickPrice handle the selection. Zero-move ticks (no price change) produce zero tickMove, so they don't inflate travel.

Non-bug observations (confirmed correct):

  • Array indexing: no ArraySetAsSeries call, code assumes chronological (index 0 = oldest). Consistent throughout. ✓
  • toTime = (nextBarStart * 1000) - 1: correctly excludes the next bar's first millisecond. ✓
  • Historical re-fetch on bar transition only (start = prev_calculated - 1 = currentBar - 1): does not re-fetch every tick. ✓
  • time[i+1] boundary when i = currentBar - 1: correctly uses live bar open time as upper bound. ✓
  • g_hasLastTick / g_currentBarTime live bar state machine: correctly initializes on bar change, accumulates on subsequent ticks. ✓
  • indicator_buffers 3 / indicator_plots 3: matches the three SetIndexBuffer calls. ✓

The flags split into two categories:

Filter flags (which ticks to return):

  • COPY_TICKS_INFO = all ticks
  • COPY_TICKS_TRADE = Bid/Ask changes
  • COPY_TICKS_ALL = Last/Volume changes

Field flags (which fields to populate in the returned struct):

  • COPY_TICKS_LAST = populate the Last field

For your purpose — actual trade prices, indecision — you want:

COPY_TICKS_ALL | COPY_TICKS_LAST

COPY_TICKS_ALL filters to trade execution ticks (Last/Volume). COPY_TICKS_LAST ensures the Last field is populated in the returned MqlTick. Without the field flag, the filter alone doesn't guarantee tick.last is non-zero.
