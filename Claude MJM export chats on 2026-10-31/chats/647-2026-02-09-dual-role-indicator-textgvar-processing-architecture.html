CHANGE PLAN: Dual-Role TextGVar Processing for IndySlopes

CURRENT STATE

IndySlopes currently operates as:

  • Consumer: Reads TextGVar data from source indicators (SIs), holds SI handles, triggers SI cleanup when IndySlopes releases SI handles
  • Producer: Exports its own TextGVar metadata but does NOT monitor for handle releases by consumers (EAs/indicators)

Missing mechanism: When consumers release IndySlopes handle → IndySlopes should detect and self-deinit asynchronously

REQUIRED CHANGES

1. OnTimer Extension

Current OnTimer behavior:

  • Monitors chart for SI count changes
  • Triggers ScanChartIndicators() when SIs added/removed

Add to OnTimer:

  • Monitor for consumers releasing IndySlopes handle
  • Detect when no active consumers remain
  • Trigger asynchronous self-deinitialization when orphaned

2. Consumer Handle Tracking

Add global tracking:

  • List/count of active consumers holding IndySlopes handle
  • Mechanism to detect handle release events
  • Flag to trigger clean deinit when consumer count reaches zero

Implementation approach:

  • Use TextGVar query to detect active consumers
  • Pattern: consumers must maintain "alive" signal in their own TextGVars
  • IndySlopes checks for presence/absence of consumer alive signals
  • Alternative: monitor handle reference count if MQL5 API exposes this

3. Deinitialization Logic Enhancement

Current OnDeinit:

  • Calls HandleIndicatorDeinit(reason, g_Ctx)
  • Kills timer
  • Releases stored SI handles

Preserve existing behavior, ensure it works for both:

  • User-initiated removal (chart cleanup, indicator deletion)
  • Asynchronous self-deinit (no consumers remain)

4. Metadata Export Verification

Current metadata export:

  • Already exports buffer metadata via ExportLineMetadata
  • Already calls FinalizeMetadataExport

Verify:

  • Exported metadata sufficient for consumers to establish handle
  • Consumers can detect IndySlopes instance ID and short name
  • Cleanup signals propagate correctly bidirectionally

IMPLEMENTATION SEQUENCE

  1. Add consumer monitoring to OnTimer()

    • Query for active consumers via TextGVar pattern
    • Count active consumers
    • Set flag if zero consumers detected

  2. Add deinit trigger mechanism

    • When zero consumers + stable check period → call ChartIndicatorDelete

  3. Test bidirectional cleanup

    • Verify: Remove SI from chart → IndySlopes detects → SI deinits
    • Verify: Remove consumer from chart → IndySlopes detects → IndySlopes deinits
    • Verify: Remove IndySlopes from chart → consumers detect → consumers deinit

REVISED CHANGE PLAN: Producer-Side TextGVar Processing for IndySlopes

CLARIFIED ARCHITECTURE

  • Producers (SIs, IndySlopes): Export metadata, clean up on removal. Do NOT monitor consumers.
  • Consumers (IndySlopes consuming SIs, EAs consuming IndySlopes): Monitor producers, manage handles, trigger own OnDeinit when producer removed.
  • IndySlopes is dual-role: consumer of SIs, producer for EAs/other indicators.

CURRENT PRODUCER-SIDE IMPLEMENTATION IN INDYSLOPES

IndySlopes OnInit() already:

  • Calls InitIndicatorContext(g_Ctx, ...)
  • Exports buffer metadata via ExportLineMetadata()
  • Creates additional plot metadata via CreatePlotMetadata()
  • Finalizes export via FinalizeMetadataExport()

IndySlopes OnDeinit() already:

  • Calls HandleIndicatorDeinit(reason, g_Ctx) for producer-side cleanup
  • Calls ReleaseStoredIndicatorHandles() for consumer-side cleanup
  • Kills timer

COMPARISON: SI PATTERN vs INDYSLOPES PATTERN

Stochastic SI (pure producer):

OnInit():
  - InitIndicatorContext()
  - ExportLineMetadata() for each buffer
  - FinalizeMetadataExport()
  
OnDeinit():
  - HandleIndicatorDeinit(reason, g_Ctx)

IndySlopes (dual-role):

OnInit():
  - InitIndicatorContext()
  - ExportLineMetadata() for each buffer
  - CreatePlotMetadata() for summary buffers
  - FinalizeMetadataExport()
  
OnDeinit():
  - HandleIndicatorDeinit(reason, g_Ctx)  ← Producer cleanup
  - EventKillTimer()
  - ReleaseStoredIndicatorHandles()        ← Consumer cleanup

IDENTIFIED GAP

IndySlopes OnDeinit() performs operations in this order:

  1. Print debug
  2. HandleIndicatorDeinit() - cleans up TextGVars
  3. EventKillTimer()
  4. ReleaseStoredIndicatorHandles() - releases SI handles

Problem: When IndySlopes deinitializes, its TextGVar cleanup happens BEFORE it releases SI handles. If SIs check for consumers during their deinit, they may see stale data.

Required: Consumer-side cleanup (releasing SI handles) should occur BEFORE producer-side cleanup (TextGVar removal) to maintain proper deinitialization cascade.

REQUIRED CHANGES

1. Reorder OnDeinit() operations

Current order:

HandleIndicatorDeinit(reason, g_Ctx);
EventKillTimer();
ReleaseStoredIndicatorHandles();

Correct order:

EventKillTimer();
ReleaseStoredIndicatorHandles();
HandleIndicatorDeinit(reason, g_Ctx);

Rationale:

  • Kill timer first (prevents new operations)
  • Release SI handles next (consumer role cleanup, triggers SI deinits)
  • Clean up own TextGVars last (producer role cleanup, signals consumers)

2. Verify REINIT handling

Confirm that when IndySlopes reinitializes (parameter change, SI added/removed), the metadata export in OnInit() properly updates with new instance ID and doesn't leave orphaned TextGVars.

Currently: InitIndicatorContext() should handle this, but verify the InstanceID changes and old entries are properly flagged for cleanup.

NO OTHER CHANGES NEEDED

IndySlopes already has complete producer-side implementation matching SI pattern. The only issue is operation order in OnDeinit().
