The Bug:

When GetInfo4IndyOnChart finds the indicator already on the chart, g_indicatorSubWindow gets set to the existing indicator's window. Since g_indicatorSubWindow != -1, the EA skips adding its indicator. But HandleIndicator still points to the newly created instance from IndicatorCreate(), not the on-chart indicator.

The on-chart indicator plants arrows (you see them). But when the EA calls CopyBuffer(HandleIndicator, ...), it reads from its separate internal instance which may have different calculation timing or state.

Why keyboard shortcuts work: They call TS_OpenPosition() / TS_ReverseOrOpen() directly without reading any indicator buffers.

Why auto-trading fails: The EA reads arrow buffers from the wrong indicator instance.

The fix: When indicator is already on chart, use ChartIndicatorGet() to get the existing indicator's handle instead of keeping the IndicatorCreate handle.

Question 1 - simple subwindow finder function:

//+------------------------------------------------------------------+
//| FindIndicatorSubwindow - find subwindow by shortname prefix      |
//| Returns: subwindow number (0+) or -1 if not found                |
//+------------------------------------------------------------------+
int FindIndicatorSubwindow(string shortNamePrefix)
{
   int totalWindows = (int)ChartGetInteger(0, CHART_WINDOWS_TOTAL);
   
   for(int wnd = 0; wnd < totalWindows; wnd++)
   {
      int indicatorCount = ChartIndicatorsTotal(0, wnd);
      for(int idx = 0; idx < indicatorCount; idx++)
      {
         string indyName = ChartIndicatorName(0, wnd, idx);
         if(StringFind(indyName, shortNamePrefix) == 0)
            return wnd;
      }
   }
   return -1;
}
