MQL5 indicator restart on line property changes

In MQL5, when a user changes line properties for an indicator, does it restart the indicator from scratch, i.e., is OnInit run again?
Claude2026-01-17 12:39 UTC

Saturday, January 18, 2026, 12:14 AM CST

No. Changing indicator line properties (color, style, width) through the chart interface does not trigger OnInit or restart the indicator. The indicator continues running with its existing state and calculated buffers intact.

Property changes made via the Properties dialog are handled internally by the terminal without reinitializing the indicator.

What does trigger OnInit:

  • Changing input parameters
  • Timeframe change
  • Symbol change
  • Recompiling the indicator
  • Manual refresh/reattach

If an indicator internally uses PlotSet... to change line properties, will those immediately affect what the user sees?
Claude2026-01-17 12:41 UTC

Yes. Changes via PlotIndexSetInteger(), PlotIndexSetDouble(), or PlotIndexSetString() take effect immediately on the next chart redraw. No indicator restart or reinitialization occurs.

The chart typically redraws on the next tick, or you can force immediate redraw with ChartRedraw().

Yes. Timer-driven color cycling is entirely feasible:

int OnInit()
{
   EventSetMillisecondTimer(100);
   return INIT_SUCCEEDED;
}

void OnTimer()
{
   static int hue = 0;
   PlotIndexSetInteger(0, PLOT_LINE_COLOR, HSVtoRGB(hue, 255, 255));
   hue = (hue + 5) % 360;
   ChartRedraw();
}

People have built pulsing signals, gradient transitions, and alert-driven color flashes this way.

Millard2026-01-17 12:43 UTC
could you make just a section of a line pulse?
Claude2026-01-17 12:43 UTC

Yes. Use DRAW_COLOR_LINE with a color index buffer.

// Buffer 0: price data
// Buffer 1: color index per bar

SetIndexBuffer(0, DataBuffer, INDICATOR_DATA);
SetIndexBuffer(1, ColorBuffer, INDICATOR_COLOR_INDEX);

PlotIndexSetInteger(0, PLOT_DRAW_TYPE, DRAW_COLOR_LINE);
PlotIndexSetInteger(0, PLOT_COLOR_INDEXES, 3);
PlotIndexSetInteger(0, PLOT_LINE_COLOR, 0, clrGray);      // index 0: static
PlotIndexSetInteger(0, PLOT_LINE_COLOR, 1, clrRed);       // index 1: pulse color A
PlotIndexSetInteger(0, PLOT_LINE_COLOR, 2, clrYellow);    // index 2: pulse color B

Then in OnTimer() or OnCalculate(), cycle the pulse color indices:

void OnTimer()
{
   static bool toggle = false;
   color pulseColor = toggle ? clrRed : clrYellow;
   PlotIndexSetInteger(0, PLOT_LINE_COLOR, 1, pulseColor);
   toggle = !toggle;
   ChartRedraw();
}

Bars you want pulsing get ColorBuffer[i] = 1. Static bars get ColorBuffer[i] = 0.

You control exactly which segment pulses by setting the color index buffer values.

can an indicator in a subwindow plot a line on the main chart window or another subwindow?
Claude2026-01-17 12:45 UTC

No, not with indicator buffers. Buffers are bound to the indicator's assigned window.

Yes, with graphical objects. ObjectCreate() accepts a subwindow index parameter:

ObjectCreate(0, "MyLine", OBJ_TREND, 0, time1, price1, time2, price2);  // 0 = main chart
ObjectCreate(0, "MyLine2", OBJ_TREND, 2, time1, price1, time2, price2); // 2 = subwindow 2

So a subwindow indicator can draw lines, labels, arrows, etc. on the main chart or any other subwindow—but not plot buffer-based lines there.

Millard2026-01-17 12:46 UTC
could an OBJ_TREND mimic a moving average, for example?
Claude2026-01-17 12:46 UTC

Technically yes, but painfully. You'd need one OBJ_TREND per bar-to-bar segment:

for(int i = startBar; i < endBar; i++)
{
   string name = "MA_" + IntegerToString(i);
   ObjectCreate(0, name, OBJ_TREND, 0, time[i], ma[i], time[i+1], ma[i+1]);
   ObjectSetInteger(0, name, OBJPROP_COLOR, clrBlue);
   ObjectSetInteger(0, name, OBJPROP_RAY_RIGHT, false);
   ObjectSetInteger(0, name, OBJPROP_RAY_LEFT, false);
}

Problems:

  • Hundreds/thousands of objects for visible history
  • Must manage creation, updates, and cleanup manually
  • Performance degrades with object count
  • No native anti-aliasing or line style consistency

Practical use cases where this approach makes sense:

  • Drawing a short highlight segment (few bars) on main chart from a subwindow indicator
  • Projection lines or forecast segments
  • Sparse markers

For anything resembling a full MA, the proper solution is a separate indicator on the main chart, or an EA that creates an indicator handle with iCustom() or iMA() on the target window.

Millard2026-01-17 12:47 UTC
Can EAs draw lines?
Claude2026-01-17 12:47 UTC

Yes. EAs have full access to ObjectCreate() and all graphical object functions. Same capabilities as indicators for object-based drawing.

What EAs cannot do: create indicator buffers. There's no PLOT_DRAW_* or SetIndexBuffer() mechanism for EAs.

So an EA can:

  • Draw OBJ_TREND, OBJ_HLINE, OBJ_VLINE, OBJ_RECTANGLE, etc.
  • Draw on main chart or any subwindow
  • Create/manage indicator handles via iCustom(), iMA(), etc. (those indicators draw their own buffers)

Common EA pattern for visual output:

  • Use objects for trade levels, zones, annotations
  • Spawn a companion indicator via iCustom() for buffer-based plots

No. Two issues:

1. Horizontal logic is correct:

int barIndex = totalBars - 1 - xBars;

totalBars - 1 = oldest bar index. Subtracting xBars moves toward more recent bars (rightward). This meets the requirement.

2. Vertical positioning is broken:

OBJPROP_YDISTANCE does not apply to OBJ_TEXT. That property is for OBJ_LABEL (pixel-based positioning).

OBJ_TEXT uses price coordinates. The code sets price to 0:

ObjectCreate(0, name, OBJ_TEXT, 0, timeCoord, 0)

This places text at price level 0—off-screen for virtually all instruments. The yOffset parameter has no effect.

Fix options:

A. Switch to OBJ_LABEL if you want pixel-based Y offset (but then X becomes pixel-based too, breaking the bar-offset logic).

B. Keep OBJ_TEXT and pass an actual price coordinate for Y positioning:

double yPrice = ChartGetDouble(0, CHART_PRICE_MAX) - (yOffset * Point() * 100);
ObjectCreate(0, name, OBJ_TEXT, 0, timeCoord, yPrice);

bool TextGVar_Create(const string prefix,
                     const string shortName,
                     const string varName,
                     const string value,
                     const int xBars = 0)
{
   string name = TextGVar_BuildName(prefix, shortName, varName);
   
   if(ObjectFind(0, name) >= 0)
      ObjectDelete(0, name);
   
   int totalBars = Bars(Symbol(), Period());
   int oldestBarIndex = totalBars - 1;
   int barIndex = oldestBarIndex - xBars;
   if(barIndex < 0) barIndex = 0;
   
   datetime timeCoord = iTime(Symbol(), Period(), barIndex);
   double pipSize = (Digits() == 5 || Digits() == 3) ? Point() * 10 : Point();
   double yPrice = iHigh(Symbol(), Period(), oldestBarIndex) + (20 * pipSize);
   
   if(!ObjectCreate(0, name, OBJ_TEXT, 0, timeCoord, yPrice))
      return false;
   
   ObjectSetString(0, name, OBJPROP_TEXT, value);
   ObjectSetInteger(0, name, OBJPROP_ANCHOR, ANCHOR_LEFT_UPPER);
   ObjectSetInteger(0, name, OBJPROP_FONTSIZE, 8);
   ObjectSetInteger(0, name, OBJPROP_COLOR, clrDarkGray);
   ObjectSetString(0, name, OBJPROP_FONT, "Consolas");
   ObjectSetInteger(0, name, OBJPROP_SELECTABLE, true);
   
   return true;
}

Changes:

  • Removed unused yOffset parameter
  • Y coordinate = high of oldest bar + 20 pips
  • Added pip size calculation for 4/5 digit brokers
