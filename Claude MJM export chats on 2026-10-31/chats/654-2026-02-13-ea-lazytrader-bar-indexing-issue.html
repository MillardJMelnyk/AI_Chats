Looking at the code with non-series arrays:

After CopyBuffer(..., 0, rates_total, ...) into a non-series array:

  • Array[0] = oldest bar
  • Array[rates_total - 1] = current bar (position 0)
  • Array[rates_total - 2] = previous bar (position 1, just closed)

The code does:

int liveBar = rates_total - 1;     // current forming bar
int checkBar = liveBar - 1;        // rates_total - 2 = just-closed bar

The indexing is correct. checkBar points to the bar that just closed, which is where the arrow would be planted.

  • Trades triggering on old/historical arrows?
  • Missing newly planted arrows?
  • Trades appearing one bar late or early?

This would help identify whether the issue is elsewhere (indicator timing, g_lastProcessedSignalBar initialization, buffer index constants, or the arrow detection condition itself).

Claude2026-02-13 21:45 UTC

The problem is CopyBuffer's start position parameter uses series indexing regardless of the target array's series flag.

CopyBuffer(handle, buffer, 0, rates_total, array) means:

  • Start from position 0 (current bar in series terms)
  • Copy rates_total elements going backward in time

Result in your non-series array:

  • IndArrowBuy[0] = current bar (forming)
  • IndArrowBuy[1] = just-closed bar (where arrow is)
  • IndArrowBuy[rates_total-1] = oldest bar

Your code checks IndArrowBuy[checkBar] where checkBar = rates_total - 2, which points to ancient history, not the just-closed bar.

Fix: Check index 1 for the just-closed bar:

//--- Check for new signal on previous bar (completed bar)
int checkBar = 1;  // Index 1 = just-closed bar after CopyBuffer from position 0

You'll also need to rework g_lastProcessedSignalBar tracking since it currently stores array indices that shift meaning each bar. Consider storing the bar's datetime instead, or simply a flag that resets each new bar.

Claude2026-02-13 21:47 UTC

BarsCalculated(iHndlIndy)

Returns the number of bars the indicator has actually calculated, which matches what rates_total was in the indicator's most recent OnCalculate call.

This is more reliable than Bars() or iBars() because it reflects what the indicator has actually processed, not just what the terminal has available. There can be timing gaps where the terminal has new bars but the indicator hasn't recalculated yet.

Two problems:

1. Copying entire history every tick

Only copy new/changed bars:

int toCopy = rates_total - prev_calculated;
if(toCopy <= 0) toCopy = 1;  // Always recalc current bar

if(CopyBuffer(iHndlTEMA, 0, 0, toCopy, tempTEMA) != toCopy)
   return(0);

2. Redundant temp arrays

Copy directly into your indicator buffers. CopyBuffer works with SetIndexBuffer arrays:

if(CopyBuffer(iHndlTEMA, 0, 0, toCopy, BufferTEMA) != toCopy)
   return(0);
if(CopyBuffer(iHndlMA, 0, 0, toCopy, BufferMA) != toCopy)
   return(0);

This eliminates the temp arrays and the copy loop entirely.

Caveat: Your buffers must be set as series (ArraySetAsSeries(BufferTEMA, true)) for this to work correctly with start position 0, or you need to adjust the start position parameter to copy into the correct array indices.
