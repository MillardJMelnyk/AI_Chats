CLAUDE2026-07-10 17:31 UTC

Two things block it, one in code and one in the tester setup.

Code: the processing-window gate throws away every tick that arrives before the window start. All warm-up — the rolling tick history the signals need, plus the self-calibrating detectors — only starts counting from the first accepted tick, so the first stretch inside your window is burned on warm-up (that's the blank gap in image 1). Fix: accept ticks starting one full warm-up period before the window start and feed them into state and calibration, but keep plots, signals, and trades suppressed until the window actually opens. The warm-up lead is already computed internally (the largest of the ratio/slope/indy lookbacks, plus roughly five minutes for the detectors' first calibration), so the early-accept boundary can be derived from it rather than added as a new input.

Tester: with the tester start date equal to the window start (both 2026.07.06), no pre-window ticks exist to warm up on, even with the code fix. The tester start date has to precede the window start by at least the warm-up lead.
