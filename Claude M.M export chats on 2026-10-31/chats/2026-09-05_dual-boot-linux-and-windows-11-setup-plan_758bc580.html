Reading the files from Linux

Works natively. The kernel's NTFS driver reads and writes NTFS, and Fedora's file manager mounts your data drives on click. No conversion, no extra partition, no Samba. You open your .mq5 and .md files in VS Code on the Linux side and they're just files.

Three things to get right:

1. Turn off Fast Startup in Windows. This is the one that bites people. Fast Startup doesn't really shut down — it hibernates the kernel and leaves NTFS volumes flagged as in-use. Linux then mounts them read-only or refuses entirely, and you'll think NTFS support is broken when it isn't. Control Panel → Power Options → Choose what the power buttons do → uncheck Turn on fast startup. Also disable hibernation.

2. Your MQL5 source has to live on D:, not C:. By default MetaTrader keeps it buried in AppData on the Windows partition. You do not want Linux reaching into a live Windows system partition — that's the one NTFS volume worth treating as off-limits. Install MT5 to D: in portable mode so its data folder sits beside it, or leave the install alone and junction the MQL5 folder out to D:. Either way the source ends up on a drive both systems can touch cleanly.

Same for the cTrader/C# project files and your .md files.

3. Line endings, if the source is in Git. Windows Git with core.autocrlf=true writes CRLF to disk; Linux Git expects LF. Open the same repo from both and the whole tree shows as modified. Set core.autocrlf=false on the Windows side and add a .gitattributes. Do this before you have two OSes fighting over it.

Once those three are set, what you described works: Windows for the actual work, Linux with full read access to everything, no flipping mid-project.

why is dual-boot its "awkward path"?

CLAUDE2026-09-09 20:35 UTC

I was wrong, and the source I used was stale.

Omarchy's installer now has a Free space install option. You shrink the Windows partition from Disk Management, boot the installer, select the disk, pick Free space install, and it leaves Windows alone. The manual documents exactly that. Afterward you run limine-scan and Windows appears in the boot menu.

That's not awkward. It's roughly what Fedora does. My claim came from a December guide written before the option existed, and I should have checked the manual before repeating it.

What is actually left on the dual-boot side:

LUKS encryption is on by default for the Omarchy partition, and it's incompatible with BitLocker on the Windows side — the manual tells you to turn Windows device encryption off first. Extra step, not a problem.

Secure Boot and TPM. Omarchy requires Secure Boot off to install. Your BIOS already has it off. The manual also mentions TPM, which is murkier — Windows 11 checks for TPM 2.0 during a clean install, so if Omarchy genuinely needs TPM disabled you'd have a sequencing conflict to work out. Fedora has no such requirement.

Limine and the stray EFI partition on Disk 1. There's a documented failure where Limine overwrites the Windows bootloader when Windows' EFI partition sits on a different drive. Both your OSes would be on Disk 2, so you're not the target case — but that orphaned 99 MB EFI partition on Disk 1 is exactly the kind of thing that confuses a bootloader installer. Another reason it goes before any of this starts.

So: strike dual-boot difficulty from the list. The tiling desktop and the rolling release are the real questions.
