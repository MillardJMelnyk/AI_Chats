The RevisionStart buffer is not appearing in the data window because of a mismatch between the buffer index and the plot index.

The problem:

  • On line 97, BufferRevisionStart is assigned to buffer index 8: SetIndexBuffer(8, BufferRevisionStart, INDICATOR_DATA);
  • On lines 108–110, you attempt to configure its display properties using PlotIndexSetInteger(8, ...) and PlotIndexSetString(8, ...)

But here's the issue: PlotIndexSet* functions operate on plot indices, not buffer indices. These are only the same when every buffer is a plot buffer in sequential order—which isn't the case here.

Your #property indicator_plots 9 declares 9 plots, and your #property directives (lines 15–55) map plots 1–9 to their visual properties. However, the SetIndexBuffer calls use INDICATOR_DATA for all buffers, which means all 9 buffers are treated as plot buffers. The plot indices 0–8 should correspond to buffer indices 0–8 in that case, so in principle plot index 8 should work.

The actual culprit: The PLOT_SHOW_DATA flag on line 110 is being set correctly, but DRAW_NONE plots with PLOT_SHOW_DATA = true still won't appear in the data window unless the buffer contains non-EMPTY_VALUE data at the cursor position.

Look at lines 186–187:

for(int i = 0; i < rates_total; i++)
   BufferRevisionStart[i] = (double)start;

This loop runs for all bars, but on the first call (when prev_calculated == 0), start is 0. On subsequent calls, start gets a value based on pivot lookback—but you're overwriting the entire buffer every tick with the same start value for all bars. That's fine for populating the buffer.

The real reason it's not showing:

Your #property declarations at lines 53–55 set indicator_type9 to DRAW_NONE. The #property directives are compiled statically and take precedence. Even though you're calling PlotIndexSetInteger(8, PLOT_DRAW_TYPE, DRAW_NONE) at runtime (which is redundant since it's already DRAW_NONE), the key issue is that DRAW_NONE plots typically don't show in the data window by default, and the PLOT_SHOW_DATA flag you set at runtime may be ignored because the #property block doesn't include an equivalent static declaration.

Bottom line: The #property block doesn't have a way to statically declare PLOT_SHOW_DATA = true. You're relying on runtime PlotIndexSetInteger(8, PLOT_SHOW_DATA, true) to enable it, but for DRAW_NONE plots, this runtime setting may not take effect reliably in all MT5 builds, or it may require the buffer to be declared as INDICATOR_CALCULATIONS rather than INDICATOR_DATA (though that would also hide it).

The most likely fix: change the plot type from DRAW_NONE to something visible but styled to be unobtrusive (like DRAW_LINE with zero width or a transparent color), or test whether your MT5 build actually honors PLOT_SHOW_DATA for DRAW_NONE plots.
