CLAUDE2026-05-06 17:56 UTC

They don't, in the same sense. Different mechanism.

CalcTEMA and CalcMA detect reset only via:
- prev_calculated == 0 (host says full recalc)
- output array size != input array size (resize happened)

If either is true, they wipe their scratch state and recompute from scratch.

What they don't detect: history rewrites where bar count stays the same. If the broker silently shifts the series — say bar 0's timestamp changes because old bars dropped off and new ones came in at the same rates_total — TEMA/MA won't notice. They'll trust prev_calculated and do an incremental update on top of stale state.

CalcZigZag adds the firstBarTime check specifically to catch that case. It was inherited from the original Ind_ZigZag code (the g_FirstBarTime != time[0] check), and I preserved it during the refactor because removing it would have been a behavior change.

So the asymmetry is real but it's by design — ZigZag is more paranoid about silent history shifts than TEMA/MA are. Whether TEMA/MA should be equally paranoid is a separate question.
