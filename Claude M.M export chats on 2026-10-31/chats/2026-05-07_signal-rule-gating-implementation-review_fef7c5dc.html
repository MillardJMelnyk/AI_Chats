# Change Plan: Make PMA and MAKCL Tick-Safe

Pattern to follow

CF's CF_PreparePendingCrossesForBar (line 2631). On first encounter of a bar index, snapshot the state. On re-encounter of the same bar, restore from snapshot before mutating. Same idea here.

PMA changes (PMA_Drive_MJM.mqh)

Add to SPMAEngineState:
- A snapshot copy of all entity states (streak_sign, streak_bars, slope_window, window_idx, window_count for all three entities)
- A snapshot copy of all pair states (prev_spread_sign, bars_since_cross, last_cross_dir for all three pairs)
- A working bar sentinel (-1 initially)

Add PMA_PrepareForBar(state, index):
- If index != working_bar: copy live state into snapshot, set working_bar = index, return.
- Else: copy snapshot back into live state.

Modify PMA_ComputeAt:
- Call PMA_PrepareForBar(state, index) at the top, before any state mutation.
- Everything else stays the same.

Modify PMA_InitState:
- Initialize the snapshot fields to match the live fields.
- Initialize working_bar to -1.

MAKCL changes (MA_KCL_Cross_MJM.mqh)

Add to SMAKCLState:
- A snapshot copy of all six pair states.
- A working bar sentinel.

Add MAKCL_PrepareForBar(state, index):
- Same logic as PMA's version.

Modify MAKCL_ComputeAt:
- Call MAKCL_PrepareForBar(state, index) at the top.

Modify MAKCL_InitState:
- Initialize snapshot to match live.
- Initialize working_bar to -1.

What does NOT change

  • The calling code in CrossFire_Channel_MJM.mq5 (lines 6108–6127). Stays exactly as-is.
  • The array outputs (pma_netDrive[], pma_makcl_drive[], etc.). Already idempotent — position-indexed overwrites.
  • The math inside PMA_UpdateEntityAndDrive, PMA_UpdatePairCrossPulse, MAKCL_UpdatePair. Untouched. The snapshot/restore wrapper makes them safe without modifying them.
  • Initialization timing. PMA_InitState and MAKCL_InitState are still called once on prev_calculated == 0.

Verification after the change

On the first tick of a new bar, snapshot captures the state as it stood at the end of the prior bar. On every subsequent tick of that same bar, restore wipes out any mid-bar mutations before the engine runs. End result: the engine effectively runs exactly once per bar from a state-mutation standpoint, but the array outputs reflect the latest tick's input values. Same behavior as CF's pending-crosses.
