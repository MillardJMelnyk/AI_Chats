# Specification: Chronicity Fixes for CrossFire_Channel_MJM.mq5

Background

This indicator processes M1 bars and emits signals (entries and exits). Each OnCalculate invocation processes bars from start_bar through rates_total - 1. The rightmost bar (rates_total - 1) is the live, in-progress bar; all others are historical, finalized bars.

A causally honest signal pipeline must respect two rules:

Rule A (intrabar decisions): A decision based on data that is known at the moment a tick arrives mid-bar may fire on that tick and fill at that tick's price. Reference price = close[n] of the live bar (which equals the latest tick's bid/last).

Rule B (bar-close decisions): A decision based on a bar's finalized OHLC, finalized indicator values, or finalized cross/penetration events cannot be acted on during that same bar. The earliest moment such a decision can act is the first tick of the next bar. Therefore: decision uses bar [n-1] data; action stamps timestamp and bar index [n]; fill price = open[n].

The current code violates Rule B in many places by detecting an event using bar i's closing data and firing on bar i priced from bar i's OHLC. The work below corrects each violation.

Decision Classification

Before fixing anything, every decision point must be tagged as either intrabar (Rule A) or bar-close (Rule B). Use this classification:

Intrabar (fires on tick t of live bar n, fills at that tick's price):
- Spike detection (TryStartSpike) — a spike is fundamentally a fast intrabar move; the test (price extending past KC by ≥ X% of width) can be evaluated each tick.
- Spike fire (ProcessSpike) — the just-jump retracement check is an intrabar event; fills at the tick price that crossed the threshold.
- Adverse-recovery exit watchdog — once armed, fires when running adverse exceeds threshold and recovery deadline passes; the recovery-reached check is intrabar.

Bar-close (decision uses bar [n-1]'s finalized values; action stamps bar [n] at open[n]):
- MA cross detection (ComputeMACross) — uses MA1/MA2 finalized values.
- Qualified-cross cycle reset.
- Reverted-mode update.
- Cocking evaluation.
- Cocked-entry condition.
- Flip-check evaluation.
- Blackout-deferred fire.
- Threshold-breach-depth gate (uses finalized close vs MA threshold).
- Spread-expansion-rate / acceleration-inflection / travel-since-raw-cross / hug-release gates (all use prior-bar deltas).
- Adverse-close-dominance exit (counts negative closes).
- Line-event clustering: test detection, cluster accumulation, cluster resolution fire, exit-reentry fire, channel commitment update.

Fix 1: Two-Pass Pipeline Restructure

for each bar i in [signal_start .. rates_total - 1]:

    # These decisions were computed and queued at the close of bar i-1.
    # They fill at open[i].

    if pending_action_from_prev_bar:
        fill_price = open[i]
        action_bar = i
        action_time = time[i]
        # Fire the queued entry/exit at open[i]
        execute(pending_action, fill_price, action_bar, action_time)
        clear(pending_action)

    # ---- PASS B: INTRABAR EVALUATION of bar i (only meaningful on
    #              rightmost bar in live mode; on historical bars, treat
    #              the bar as a sequence of "ticks" implicitly) ----
    #
    # On historical bars, intrabar pipelines collapse to a single check
    # using bar i's high/low/close (the bar's OHLC contains all the
    # intrabar excursion information). Spike start/process and adverse
    # recovery checks fire here. Fills are intrabar prices, not open[i+1].

    run_intrabar_pipelines(i)

    # ---- PASS C: BAR-CLOSE EVALUATION (decide using bar i's finalized data) ----
    #
    # All bar-close pipelines run here. Any decision that fires QUEUES
    # a pending action for bar i+1.

    run_bar_close_pipelines(i)        # cocking, cross, cocked entry, flip,
                                       # blackout deferred, line-event clusters,
                                       # commitment, gates, adverse-close-dominance

        pending_action = (direction, source, is_spike=false, etc.)
