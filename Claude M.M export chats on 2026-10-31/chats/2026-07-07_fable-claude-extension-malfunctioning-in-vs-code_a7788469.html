CLAUDE2026-07-07 16:14 UTC

Nothing broke — you hit a head-on collision between your rules and the model's training. Agentic coding models are trained hard on two reflexes: treat "can you do X" as an instruction to do X, and gather context (read files, glob, run commands) before saying anything. Your AGENTS.md inverts both — first response one sentence, nothing without GO. When the two conflict, the trained reflex usually wins on the first turn, because the model starts acting before it's fully weighted your rules. That's why it read AGENTS.md as one of its investigation steps while already violating it.

Two things make it worse in the VS Code extension:

Hypothesis: AGENTS.md isn't auto-loaded. Claude Code / the Claude extension auto-loads CLAUDE.md from the project root; AGENTS.md is the Codex convention. If your rules only exist in AGENTS.md, Fable starts every chat blind to them until it happens to read the file — which is after it's already charging. Fix: copy the rules into C:\Temp-C\MQL5\CLAUDE.md (or symlink). That puts the GO gate in context from turn one.

Second: every time you killed it mid-tool-use, the transcript got littered with truncated tool calls, which degrades the next turn. New chat was the right move; the mistake just repeated because the underlying rule-loading problem repeated.
