Let me read through all three files first.

Here's what Rob built — three indicators that form a layered system, all anchored to the same core concept.

The core idea across all three: Take the standard MetaTrader ZigZag indicator's pivot points, average the last N of them (default 3), blend that average with the current close using a configurable weight, then SMA-smooth the result. That produces a "ZigZag-aware moving average" — a line that tracks where price structure has been pivoting, pulled toward current price so it doesn't just sit on stale pivots.

Indicator 1 — AverageOfZigZag (the foundation line)

This is the base layer. It draws a single cyan line on the chart. At each bar it looks backward for the last InpAvgPeriod ZigZag pivot values, averages them, then blends that average with the current close via a weighted formula: (avgZZ + close × weight) / (1 + weight). With the default weight of 1.5, current price has more pull than the pivot average. The raw blend is then SMA-smoothed over InpSmoothing bars (default 5) to reduce noise. The result is a line that sits somewhere between "where pivots have been" and "where price is now," smoothed out.

Indicator 2 — AverageZigZagBands (bands around the foundation)

This takes the same middle line from Indicator 1 and adds upper and lower bands. The band offsets are computed by looking back at the last InpOffsetLookback (default 5) ZigZag pivots that fell above and below the middle line, separately averaging how far those peaks and troughs deviated from it. So the upper band represents the average peak overshoot and the lower band represents the average trough undershoot. It's conceptually similar to Keltner or Bollinger bands, but the volatility envelope is driven by ZigZag pivot distances rather than ATR or standard deviation. One difference from Indicator 1: the ZigZag path search is hardcoded to "Examples\\ZigZag" only (no fallback paths), and there's a sanity filter (< 1000000) on ZigZag values.

Indicator 3 — IntegralPriceToZigZagAverage (oscillator measuring distance from the line)

This is a separate-window histogram. It recomputes the same smoothed ZigZag average from Indicator 1 internally (using local arrays rather than indicator buffers), then measures how far price extends beyond it. When close is above the average, the bar shows high - average (lime). When close is below, it shows low - average (red, and the value is negative). So it's measuring the maximum directional extension of price away from the ZigZag average on each bar — not just close-to-average distance, but the furthest reach (high or low depending on side). One structural note: this indicator does a full recalc every tick rather than incremental updates, which will be slow on large datasets.

In summary: Rob built a ZigZag-derived adaptive midline, wrapped bands around it sized by actual pivot deviations, and then built an oscillator that measures how stretched price is relative to that midline. The system is trying to characterize where price "should be" based on structural pivot history and flag when it's overextended.

CLAUDE2026-04-08 15:34 UTC

Got it. So Rob's concept is to use the indicator framework as the event generator and then run binomial probability on top of it.

The indicators define the conditions — "did the candle touch the ZigZag average?" or "did price reach the upper band?" — and that gives you a binary outcome per bar: success or failure. You pick a window of N bars (trials), count how many successes (x), and from that you can compute the probability of seeing exactly x successes in N trials using the binomial formula:

P(X = x) = C(n,x) · p^x · q^(n-x)

Where C(n,x) is the combinatorial term (how many ways to arrange x successes in n trials), p is the observed probability of the event happening (successes / total bars in some reference period), q is 1-p, and you raise each to the number of times it did and didn't happen.

The practical use would be something like: if historically price touches the ZigZag average 60% of the time within a 10-bar window, you can ask "what's the probability it touches it at least 7 out of the next 10 bars?" — which tells you whether current behavior is statistically normal or anomalous relative to the baseline.

The indicators themselves don't do this yet. They just provide the raw machinery — the average line, the bands, and the distance histogram — that would define what counts as a "success" event. The binomial layer would sit on top, either as a separate indicator or in a script/EA, consuming those outputs and computing probabilities from them.
